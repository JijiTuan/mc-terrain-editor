## Minecraft 地形编辑器 — 从「能打包」到「实机验证通过」

### 交付物
`D:/ai工作区/我的世界地形编辑器功能`，v1.1.0。Vite 5 + 原生 ESM + Three.js 0.169，
无前端框架。约 25 个源文件，31 个模块。

### 本次实机验证发现并修复的 5 个真 bug

前一轮只跑通了 `npm run build`，**渲染器/UI/AI/存储/IO 全部没执行过**。
这一轮用真实 Chromium 驱动，暴露出的问题按发现顺序：

1. **`setPreview({bounds, affected} = {})` 传 null 会崩**
   `main.js:190` 调 `setPreview(null)`。JS 的解构默认值 `= {}` **只兜 undefined，不兜 null**，
   直接解构 null 抛 `TypeError`。整个应用启动即死。
   改法：`setPreview(options) { const {bounds, affected} = options || {} }`。
   → 教训：写 `= {}` 不等于「参数可为空」。

2. **boot() 初始化顺序错误**
   `setupWorld()` 内部会 `refreshAll()` 触发整块 UI 重建，而 UI 要读 `app.ai`，
   但 `setupAi()` 排在 `setupWorld()` **之后** → 首帧刷新踩 undefined。
   改法：改为 `buildShell → setupCloud → setupAi → setupStore → setupBridge → setupWorld`；
   同时给 `refreshAll()` 每个子系统加就位判断，让顺序不再是唯一防线。

3. **`ID()` helper 丢弃 `extra` 参数**（最隐蔽的一个）
   `op-schema.js` 里 `NUM(desc, extra={})` 收 extra，但 `ID = (desc) => ({type:'block', desc})`
   **只收 desc**。于是 `ID('次表层方块', {default:'dirt'})` 里的 default 被静默丢掉，
   调用方以为给了默认值，校验时照样报「缺少参数」。
   改法：`ID = (desc, extra={}) => ({type:'block', desc, ...extra})`。
   → 教训：同族 helper 的参数签名要一致，否则静默丢参数。

4. **schema 默认值与执行器兜底值漂移**
   `terrain` 的 `surface/sub/base` 与 `layer` 的 `top/middle/bottom` 在 schema 里是必填，
   但 executor 本来就有兜底（`?? 4` / `?? 3` / `?? 1`）。
   结果是模型说「生成一片山地」却不写 sub 就被拒，而执行器完全能处理。
   改法：schema 补上 default，且与执行器对齐。

5. **river 兜底液体指向岩浆块**
   executor 写 `water: op.water ?? 25`，但 `blocks.js` 里 **id 25 是 magma_block，id 26 才是 water**。
   裸数字与方块表行序强耦合。改法：建 `FALLBACK` 映射，一律 `resolveBlockId('water')` 查表，不写裸数字。

另修 `server.js`：缺失的带扩展名资源原先会回退到 index.html，
浏览器拿到 text/html 当 JS 执行，报「MIME type 不对」这种绕远路的错，
把「资源不存在」的真因盖住了。改为 404。

### AI 操作链路的核心正确性断言

**预览改动数 === 执行改动数**。这次四类 op 实测：

preview `totalChanges` 与 apply 返回值**都是 3575**，`previewMatchesApply: true`。

之前怀疑 `scatter=0` 是 bug，做了**反向对照**排除：

- 探针里 `import('/src/...')` **只在 dev server 有效**，生产构建模块已打包，
  import 会 404 并被 SPA 回退成 HTML。生产环境要走 app 暴露的 `__test__` 入口。

### 操作确认卡「看不见确认执行」—— 三个 bug 叠加

用户报「提示等待确认，但界面上找不到确认按钮」。实测定位到三个独立缺陷：

1. **卡片被 flex 压成 1px（主犯）**：`.ai-messages` 是 `display:flex; flex-direction:column`，
   `.op-card` 作为 flex item 默认 `flex-shrink:1`。消息一多就被按比例压扁 ——
   实测卡片高度从 `163px` 压成 **`1px`**，内部内容（含按钮）溢出到卡片外，
   按钮虽在 DOM 里但视觉上飘出去、点击区也错位。修：`.op-card` 和 `.msg` 都加 `flex: none`。
2. **滚动指令作用在游离节点**：`renderMessages()` 末尾 `host.scrollTop = host.scrollHeight`，
   但此时 host 还没被 `appendChild` 进 DOM。**游离节点没有布局、scrollHeight 恒为 0**，
   这句等于把滚动归零、完全无效。
3. **旧滚动位置覆盖新内容**：`buildAiPanel()` 整个重建面板后执行
   `msgs.scrollTop = <重建前的旧值>`，新卡片在下面、视线被拉回旧位置。

**反向对照证伪（不是假绿）**：撤掉 `flex:none` 跑一遍，故障精确复现 ——
卡片 `h:1`、`actionsVisible:false`、按钮 top=602 超出消息区底边 498；
加回后 `h:163`、`actionsVisible:true`、top=440。

**关键教训：`renderMessages` 里不能设 `scrollTop`** —— 它执行时 DOM 还没挂载。
滚动必须在挂载后、下一帧布局稳定时做（分帧 `requestAnimationFrame` 钉两次，
因为刚 append 时 scrollHeight 读到的是偏小旧值，实测差 125px）。
另外"出现新待确认卡片"要强制拉回视线，优先于"保持用户之前的滚动位置"。

1. **原版 1.17+ 贴图用 4 位调色板 PNG**（`colorType=3, bitDepth=4`，每字节塞两个索引）。
   只处理 8 位/RGBA 的解码器第一步就崩在 `cobblestone.png`。

3. **`NearestFilter` 是像素感的关键开关**。默认线性过滤会把 16×16 贴图糊成渐变。
   同时关 `generateMipmaps`，否则远处也糊。

  `[0.88, 0.94, 0.97, 1.00]` 四种灰度 —— 证明旧的假光照已彻底移除。

  砂岩、深板岩、石英块。

### 二、贴图来源改为官方 1.21.1 jar（重写 build-textures.mjs）

**旧做法的两个真问题**：① 手写 `BLOCK_TEXTURES` 映射表会跟游戏实际不符
（草方块侧面是 `grass_block_side` + `grass_block_side_overlay` 两层叠出来的，
砂岩底面和顶面是两张不同的图）；② 1.16 材质包没 deepslate/tuff/calcite，直接缺图退出。

**新做法**：从 jar 里走 `blockstates → models(顺 parent 链) → textures` 自动推导。

发现并修掉的坑：

1. **`unzip` 在 Node 里调不到** —— 终端能跑，`spawnSync` 报找不到命令
   （Git Bash 的 PATH 没被继承）。改成**自己解析 zip 中央目录**
   （EOCD → CD 表 → 本地头 → zlib.inflateRawSync），零外部依赖。
2. **贴图名前缀不统一** —— 模型 JSON 里同时存在 `minecraft:block/oak_leaves`、
   `block/dirt`、`dirt` 三种写法。不归一化会出现「同一张图被当三张烘三遍」，
   而且 `TINT`/`COMPOSITE` 用短名写的表**永远匹配不上** ——
   表现为染色静默失效、无色无警告。加了 `shortTexName()` 在入口统一。
3. **液体查不到** —— 水/岩浆的模型 JSON 只有 `particle` 贴图，
   六面由引擎渲染。加了 `FACE_OVERRIDE` 显式指定。
4. **草方块侧面要合成** —— 只用 `grass_block_side` 会得到一圈枯黄边，
   加 `COMPOSITE` + `alphaOver` 把 overlay 叠上去。
   实测平均色 `[120,97,63]`（泥土混草的棕绿），而不是纯泥 `[134,96,67]`。
5. **染色常量来自官方** —— `minecraft-data` 的 tints.json 里
   plains grass = `0x79c05a`、birch_leaves = `0x80a755`、spruce_leaves = `0x619961`，
   不是猜的。水也用 `0x3f76e4` 染（否则是灰色水）。

实测图集颜色：草顶 `[70,111,52]`、橡树叶 `[41,102,13]`、云杉 `[48,76,48]`、
白桦 `[65,84,43]`、水 `[44,82,159]` —— 全部合理。图集 256×64 / 62 格 / 13.3 KB。

顺带修正的映射：砂岩底面现在正确解析为 `sandstone_bottom`（旧手写表错写成 `sandstone_top`）。

### 三个关键设计取舍（都写进了代码注释）

1. **单击判定放在 `pointerup`，不放 `pointerdown`** —— 按下就放方块的话，
   用户想转视角手抖点一下就会多一个方块。位移 > 4px 才算拖拽。
2. **拖拽按格去重**（`lastCellKey`）—— 不去重的话一次拖拽往撤销栈塞几十条命令。
3. **方块模式按格提交，不是整条拖拽一条命令** —— 用户铺路铺到一半发现方向错了，
   要能一格一格退。

### 修掉的两个真 bug（都是这次探针逼出来的）

1. **`frameWorld()` 被 `snap()` 反向覆盖（严重）**
   `frameWorld` 先写 `_targetAz = PI*0.25`，再调 `snap()`；而 `snap()` 的实现是
   `this._targetAz = this.azimuth` —— **拿旧值回填目标**，把刚算好的角度冲掉。
   结果是「适应视图】按钮在用户转过视角之后**完全无效**，相机停在原地。
   **定位手法**：用 `Object.defineProperty` 给 `_targetAz` 装 setter，
   把每次写入的调用栈打出来 —— 一眼看到 `snap()` 是第二个写入者。
   修：新增 `jumpTo()`（先写 current 再 snap）；`setView()` 保留阻尼只写 target。

2. **`setPointerCapture` 没有对应的 `releasePointerCapture`**
   `onDown` 捕获指针（拖到画布外也能收到 up），但 `onUp`/`dispose` 从不释放。
   捕获会一直挂在 canvas 上，后续事件被改派到 canvas，坐标判断错位。
   修：记录 `pointerId`，`onUp`/`dispose` 里 `try/catch` 释放。

### 探针的假绿灯防御（教训延续）

- **反向对照必须带活性断言**。第一版「短路后世界未变」在**整条链路全死**的情况下
  也会通过。加了 `反向对照·钩子被触发`（`hookCalls > 0`）后，链路死掉时这个对照
  自己就会先失败。
- **钩子必须埋在闭包层，不能替换 App 方法**。`InteractionController` 在构造时把
  回调捕获进闭包，事后 `app.onCellEdit = ...` 永远看不到。改在 `setupInteraction`
  里读 `extraCallbacks.probeHooks`，闭包内先问钩子。
- **puppeteer-core 25.12.0 的方法叫 `evaluateOnNewDocument`**，不是文档里的
  `addInitScript`（调错报的是光秃秃的 `TypeError`，不是参数错误）。
- **拖拽断言不能比总方块数** —— 沿地表横拖多半落在已有石头上，`set()` 返回 false，
  好拖拽被判失败。改为统计**不同目标格数**。
- **加了 `拖拽路径不在世界边界上` 立刻抓到真问题**：落点全是 `x=0` 侧壁，
  说明相机被上一次 orbit 测试留在侧向，路径退化但断言照样绿。
- **`settleCamera()` 要求连续 3 帧稳定**才认为收敛 —— 单帧 delta 小可能只是
  「刚好路过」。azimuth/polar 容差收到 `0.0005`。

### 建仓过程中的三个坑（可复用）

**1. `git add -A` 差点吞掉 1.3 GB 垃圾**

第一次暂存扫进了 `.rename-probe2`（537MB）、`.rename-probe3`（269MB）、
`.rp6`（537MB）—— 全是当初排查「`release/` 里 `default_app.asar` 删不掉」
时建的目录重命名实验目录，每个塞着一整份解压好的 Electron。
**教训：新建仓库第一次 add 之前，一定先 `git status --short | wc -l` 看一眼数量，
再看有没有超大的。** 已加进 `.gitignore`：`.rename-probe*/`、`.rp[0-9]*/`、
`.run-probe.mjs`、`.wbapp_*.genie`、`.mc-data-tmp/`、`release6~8/`。

**2. 这台机器的代理会在「TLS 中间人」和「直通」两种模式间切换**

- 一开始：`schannel` 报 `CRYPT_E_NO_REVOCATION_CHECK (0x80092012)`。
  走 `127.0.0.1:57709` 代理后用 `curl -k` 拿到 200，确认是证书问题不是网络不通。
  用 `openssl s_client -proxy 127.0.0.1:57709 -connect api.github.com:443 -showcerts`
  取出证书链，发现签发者是 **`SteamTools Certificate`**（自签根，在
  `Cert:/CurrentUser/Root` 里），拿它当 CA 就验证通过了。
- 后来：代理**不拦了**，证书链变成真的 `github.com → Sectigo DV E36 → Sectigo Root E46`。
  这时再信任 SteamTools CA 反而失败（`unable to get local issuer certificate`）。
- **结论：代理模式会变，git 配置要跟着切。** 两种情况的判据：
  ```
  openssl s_client -proxy 127.0.0.1:57709 -connect github.com:443 -showcerts </dev/null 2>/dev/null | grep -E "^ [0-9] s:"
  ```
  看到 `SteamTools` → 配 `sslBackend=openssl` + `sslCAInfo=<SteamTools根>`；
  看到 `Sectigo`/真证书 → 改回 `sslBackend=schannel`，删掉 `sslCAInfo`。
- 另外代理**间歇性返 502**（`CONNECT tunnel failed, response 502`），
  **重试即可**，不是配置问题。推送那次是第 1 次重试就成功的。

**3. fine-grained token 的权限是「按仓库」勾的，新建仓库不在授权列表里**

用户给的 `github_pat_...` 是 fine-grained token，初始状态**三个权限全是空的**
（仓库访问 / 用户权限 / 仓库权限 都显示 None）。表现：
- `POST /user/repos` 建仓库 → `403 Resource not accessible by personal access token`
  （新建仓库需要 **Administration: read/write**，而 fine-grained 只能对**已存在**的
  仓库勾这个权限 → 死循环，所以**建仓库只能用 classic token 或网页手动建**）
- `git push` → `403 Permission to JijiTuan/mc-terrain-editor.git denied to JijiTuan`

  **修法**（token 详情页 → 编辑）：仓库访问改成「仅选择仓库 + 勾上目标仓库」，
  仓库权限里 **Contents → Read and write**。改完**同一个 token 继续用，不用重新生成**。
  注意中文界面的「选择仓库权限」列表里 `Contents` 排在很后面，**用搜索框搜
  `contents` 最快**。

### Anvil 格式的三个关键坑

1. **现代 MC 用 zlib(2)，不是 gzip(1)。** 按 gzip 解压会报 "invalid header"。
   `DecompressionStream('deflate')` = zlib 包裹；`('gzip')` = gzip；`('deflate-raw')` = 裸 deflate。
2. **位打包的索引不能跨 long 边界。** 位宽 = `max(4, ceil(log2(palette)))`，
   `perLong = floor(64/bits)`，正确的 `longIdx = floor(i/perLong)`；
   写成 `i*bits` 在第一个 long 边界之后就全错（`test-anvil` 里那个对照实现从 index 12 开始失败）。
   Section 内索引顺序是 `y*256 + z*16 + x`。
3. **写回只动方块数据。** `block_entities` / `Heightmaps` / `InhabitedTime` / `DataVersion` /
   `Status` 必须原样保留 —— 丢了箱子内容或高度图，存档就坏了。未触碰的区块**逐字节复制**，
   不重新压缩（避免无意义的字节漂移）。

### 写盘安全（重要，别简化）

`world:writeRegion` 处理器：**先备份再写**，且用 tmp + rename 原子替换：
```
target.mca.bak-<ISO时间戳>   ← 原文件先复制一份
target.mca.tmp-<pid> → rename → target.mca
```
实测备份与写前文件**逐字节一致**。

### 坐标系统不一致（结构性问题）

编辑器是「原点 0 的固定尺寸世界」，存档是「无限世界」。用 **window 选择**调和：
用户选维度 / 每边区块数（2–8）/ 最小 Y / 高度 / 起始区块。
负区块坐标要 `((c % 32) + 32) % 32`，否则 region 内局部索引为负。

### 探针排查过程（三段，全是环境坑）

**坑 1：本机回环请求被塞进代理。** shell 里 `http_proxy=http://127.0.0.1:51397`，
Node `fetch` 连 `127.0.0.1:9335` 也走代理 → `UND_ERR_SOCKET`。
修：本进程 + 子进程都设 `NO_PROXY=127.0.0.1,localhost,::1` 并删掉四个 proxy 变量。
**运行期改 `process.env` 是有效的**（undici 惰性读），不必用命令行前缀。

**坑 2（真正的元凶）：single-instance 锁 + 秒退。**
应用有 `app.requestSingleInstanceLock()`。上一轮失败残留的实例还活着时，
新起的进程会 `app.quit()` 以 **code 0 立刻退出** —— 而 Chromium 在退出**前**已经打印了
`DevTools listening on ws://127.0.0.1:9335`。于是现象是
「stderr 说在监听，探针永远 ECONNREFUSED」，看起来像产物坏了或代理问题。
**修：探针启动前 `taskkill /F /IM <exe> /T` 清场 + 轮询等端口真正空出。**
`child.kill()` **不够** —— Electron 是「主进程 + 子进程」，kill 只杀最外层，
残留渲染进程仍持有锁，把下一次运行也毒掉。必须 `/T` 连子孙一起收。
→ 教训：探针要自己保证进程卫生，不能假设环境干净。

**坑 3：探针 `import('/src/...')` 在生产构建下 404。**
打包后解析成 `file:///D:/src/io/anvil.js`。这是在**上一轮就写进备忘**的坑，
这次仍然踩了 —— 因为新写探针时没回头看。
修：在 `app.__test__` 加 `loadWorldSaveModules()` 返回模块句柄（函数没法跨 `evaluate` 传，
所以交出「拿到模块的入口」，让探针在页面里自己组合）。
→ 教训：**新探针开工前先翻 MEMORY 里的「环境坑」**，别重复踩。

### 另外两个探针自身的错误

- **跨 `evaluate` 的 `Uint8Array` 会变成 `{0:..,1:..}`**，`.length` 是 `undefined`。
  长度要在页面内取，返回值必须是纯数字。顺手加了更强的断言：
  **gzip 魔数必须是 `1f 8b`** —— 如果 IPC 把它当 UTF-8 处理过，前两位一定不是这个。
- **Bash 后台起的 vite 被沙箱杀掉**（备忘里也写过）。改用 PowerShell `run_in_background`。
  但 PowerShell 的 `npx.ps1` 被执行策略挡（`UnauthorizedAccess`），
  而且 `Start-Process cmd.exe` 被安全策略拒。**最终可行解：直接
  `& "<node.exe 绝对路径>" ".\node_modules\vite\bin\vite.js" --port 5199 --strictPort`。**

### vite 只监听 IPv6（容易误判成"服务器没起来"）

vite 默认绑 **`[::1]:5199`（IPv6）**，不绑 IPv4。`curl 127.0.0.1:5199` → 000，
`curl localhost:5199` → **200**。`netstat -ano | grep 5199` 能看到 `[::1]:5199 LISTENING`。
→ 判据：**先用 `netstat` 确认在监听，再挑 `localhost` 而不是 `127.0.0.1`。**
