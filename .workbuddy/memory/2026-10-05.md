# 2026-10-05

## v1.8.1 — 修复桌面版导出报错（两层断点）

用户报「桌面版点导出有报错」，截图实锤：
`导出失败: Failed to execute 'createObjectURL' on 'URL': Overload resolution failed.`

### 两层根因（探针逐层定位）

**第 1 层：renderer 侧 Blob 包装缺失（报错的直接来源）**
`exportSchematic()` 返回裸 `Uint8Array`（`return gzipBytes(raw)`），但导出对话框的
`doExport()` 把返回值**不包 Blob** 直接传 `downloadBlob` →
`URL.createObjectURL(Uint8Array)` 必报 Overload resolution failed。
而 `exportWorld()` 那条路径（AI 面板/快捷入口）包了 `new Blob([bytes])` 所以没事 ——
**同一模块两个调用点对返回类型的假设不一致**，这正是单元测试测不出来的那种缝
（test-io 只测字节正确性，测不到 UI 侧怎么消费）。
注意：`exportSchematic` 顶栏对话框的 .schem 分支**从写下来就是坏的**，
native/.json 分支一直是好的。

修：`doExport()` 里 `new Blob([bytes], { type: 'application/octet-stream' })`。

**第 2 层：主进程没有 will-download 处理器（修完第 1 层后立刻暴露）**
Blob 修好后 dev 全绿，但**真实打包 Electron 里文件永远不落盘**：
Chromium 默认下载在本机停在 `.tmp` **15 秒不收尾**，应用一退出就被清掉。
toast 还说着「已导出」，用户照样找不到文件 —— 第二个「导出成功但没有文件」。

修：`electron/main.cjs` 加 `session.defaultSession.on('will-download')`，
弹**原生保存对话框**（与开存档/导入风格一致），`item.setSavePath(choice)`，
取消则 `event.preventDefault()`。
探针用的测试脚手架：环境变量 `MC_EXPORT_TEST_DIR` 存在时跳过对话框直接落盘
—— 否则 headless 探针点不了原生对话框，桌面端到端没法自动化。

### 验证（两层各自有探针）

- `tools/diag-export-dialog.mjs`（5 项，dev + 打包通用）：走真实 UI 点到
  对话框「导出」按钮，钩住 `URL.createObjectURL` 断言收到 Blob、toast 无报错。
  修复前 3 红（含与用户截图一字不差的报错文案）= 天然反向对照。
- `tools/diag-export-desktop.mjs`（4 项，真实打包 Electron）：
  创建 Blob → 无报错 → **文件真落盘到测试目录**（5.4 KB）→ 文件头 gzip 魔数 `1f 8b`。
- 回归：electron-verify 全过 / test:io 37 / test:anvil 34 / test:world 20 /
  smoke 0 失败 / diag-export-dialog 5。

### 经验

- **「toast 说成功」不等于「文件存在」**。导出类功能的端到端必须验到磁盘上
  出现文件（甚至验魔数），只断言 UI 提示会漏掉第 2 层这种断点。
- 同一函数被两个调用点用不同方式消费返回值 = 定时炸弹；改返回类型签名时
  必须 grep 全部调用点。
- 原生对话框让桌面端到端没法自动化 —— 主进程侧留一个环境变量短路
  （`MC_EXPORT_TEST_DIR`）是务实的测试缝，和 renderer 侧 `__test__`/probe-hooks 同一思路。
